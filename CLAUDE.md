# Live by Scoreboard — project context for Claude Code

**Name: Live by Scoreboard** (not "Rinkboard"; that old name survives only in localStorage keys `rinkboard:*` and the Supabase project name, kept so saved logins/keys still work). Web-based ice hockey scoreboard (React + Vite, hosted on Vercel, live sync via Supabase).
**Production: https://livebyscoreboard.vercel.app** (Vercel project `livebyscoreboard`, auto-deploys main). Supabase project `rinkboard` (ap-southeast-1). The old Vercel project `rinkboard` is deleted; use only livebyscoreboard.
Owner: Pai. Built for the "3on3 Paradise 2026 OCT" tournament and future rink use; also used as an OBS overlay for streams.
Reference product we are mirroring: PC Scoreboards "Hockey Scoreboard Pro v3" (Windows desktop) and ScoreLeader's public-link model.

## Run / build

```bash
npm install
cp .env.example .env     # VITE_SUPABASE_URL / VITE_SUPABASE_ANON_KEY are REQUIRED; without them every route shows Setup.jsx
npm run dev              # http://localhost:5173
npm run build            # dist/ (Vercel builds this automatically)
```

**Cloud mode only.** Production never falls back to a local store: no keys → `Setup.jsx` with the setup steps. The same-browser local store (localStorage + BroadcastChannel) still exists in `sync.js` but only for the test build (`npm run build:test` = `vite build --mode test`, which loads `.env.test` → `VITE_ALLOW_LOCAL=1`). Decision made after a tournament-day mix-up where Chrome and OBS each had their own "copy" of the game.

**Offline desktop app** (`desktop/`, see desktop/README.md): Electron wrapper for one computer + HDMI. `npm run build:desktop` = `vite build --mode desktop` (`.env.desktop`: `VITE_DESKTOP=1`, `VITE_ALLOW_LOCAL=1`) → `desktop/web`; `sync.js` `DESKTOP` forces the same-computer store (ONLINE false, no login), `fonts-offline.js` bundles the fonts (vite.config drops the Google Fonts links in that mode), Control hides Home/QR. `desktop/main.cjs` serves the build on `app://scoreboard`, opens `/c/main` maximized on the primary screen and `/b/main` full screen on the external screen (re-placed on display-added/removed), autoplay allowed. The control window always opens in front and keeps the keyboard (scoreboard `showInactive`); F2 switches control ↔ scoreboard. One screen / Windows "Duplicate": the scoreboard waits behind the control (Win+P → Extend for HDMI). Windows builds: `.github/workflows/desktop.yml` (windows-latest → .msi + setup .exe + portable .exe + `latest.yml` as GitHub Release `v1.0.<run_number>`; the version is set from the run number). **Auto-update** (`desktop/updater.cjs`, electron-updater, GitHub provider): Setup .exe installs download updates in the background and install on quit or Control → "Update … ready · Restart" (`src/DesktopUpdate.jsx` via `window.desktop` from `desktop/preload.cjs`, control window only); never mid-game on its own. .msi/portable only read `latest.yml` and offer the download page. **Online link + Telegram** (`desktop/share.cjs`, `src/DesktopShare.jsx`, Control → 🌐 Online link, off by default): local read-only server on 127.0.0.1:47615 (only `/b/*`, `/o/*`, static files, `/api/state/<id>` long poll; everything else redirects to `/b/main`), fed by the control window's local store (`window.desktop.publishState`); Cloudflare quick tunnel via cloudflared (downloaded on first use); the link is reported/sent to Telegram only after "Registered tunnel connection". Viewers run the desktop bundle over http → `VIEWER` in sync.js = `viewerStore` (long poll, clock offset from the desktop's `now`). **Remote controllers** through the link (no website involved): `/c/main` (+ `?rink=a|b`) are served too; via the tunnel (Cloudflare headers `cf-ray`/`cf-connecting-ip`) the link must carry the app's secret `?key=` (`settings.controlKey` in share.json, 24 hex; only in the links the sheet shows and Telegram gets): first visit → HttpOnly cookie `lbs_sid` (12 h, in memory) + redirect without the key; then the cookie is enough. "🔑 New controller key" makes old links/cookies useless and re-sends the links. On 127.0.0.1 no key. A remote controller's changes: `viewerStore.set` → `POST /api/state/<id>` → `share:remote` IPC → the control window's local store (`onRemoteState`), which saves/publishes; newest `updatedAt` wins. The Telegram message and the share sheet list every board and controller (`links()` in share.cjs). (An earlier web-login handoff was dropped; its unused DB objects `login_handoffs` + `handoff_create/redeem` are still in Supabase and can be dropped.)

## Architecture

- `src/game.js` — **pure** state model + mutations. No React, no network. All hockey logic lives here (clock, periods, penalties, strength 5v4/4v3, timeouts, goal flash). Keep it pure.
- `src/options.js` — options schema + `defaultOptions()` + `withDefaults()` (deep-merges defaults into older saved games). Add new options here first.
- `src/sync.js` — store abstraction. Supabase realtime when env keys set; local store only when `VITE_ALLOW_LOCAL=1` (test build), otherwise `createStore` throws and App shows Setup. Reads are public; **writes go through `save_game(id, key, state)` RPC** which checks the operator key. Rapid taps are coalesced (~80 ms). `createGamesList()` feeds the `/live` page (table-wide realtime, or a localStorage scan).
- `src/i18n.js` — control-page UI strings (`en`, `th`), `translator(lang)`. Chosen by `opts.uiLang` (Options → Text). Display labels are separate free text in `opts.labels`. Options tab names + Save/Cancel are translated; the Options body is still English.
- `src/useGame.js` — React hook `useGame(gameId, {key, canWrite})` → `[state, update(fn), access]`. `update` takes a function `(state) => newState` (use game.js mutations). `useGameId()` parses `/b|c|o/CODE` or `?g=`.
- `src/useOptions.jsx` — `useAppearance(s)` applies theme/colors/font to `<html>`; `useGameSounds(s, enabled)` plays configured sounds on events (display side only).
- `src/horn.js` — Web Audio playback. Samples from `public/sounds/*.mp3`: `horn-nhl` (4.2 s, the default goal horn) and `horn-nhl-short` are an NHL-style three-chime air horn synthesized by `scripts/make-nhl-horn.py` (no recordings used); horn, horn-short, horn-loop, buzzer are converted from PC Scoreboards WAVs (mono 48 kbps) are decoded once after `unlockAudio()` (needs a user gesture); synth horn/buzzer/beep are the fallback. `playSound(kind)` takes a `SOUND_CHOICES` value from options.js. Goal horns 2 s or longer (horn-nhl, horn, horn-loop, synth) fade out over their last second (`HORN_FADE_SEC`); short horns and the buzzer play as they are.
- Event types in `events[]`: shot, offside, goal, penalty, penaltyEnd, timeout, so.
- Penalty call on the display: a new penalty shows "PENALTY · team" over "#12 HOOKING 2:00" for 5 s in the `.evslot` (`state.penaltyCall`, `penaltyCallActive`, `PENALTY_SHOW_MS`; a 2nd penalty on the same player within 2 s joins it: "#7 FIGHTING 5:00 + GM"; follows edits, gone if removed). GOAL! wins; otherwise the newer of offside / penalty. The penalty boxes still show only number + time (IIHF arena style). Long text shrinks to fit (`72 / length` u).
- **Small ice** (`opts.smallIce`, chosen on Home "Full rink / Small ice" → `/c/CODE?mode=small`, or Options → Game → Rink): two games on one rink sharing ONE clock, period, whistle, timeouts and shift. Rink A = the normal state fields, Rink B = `state.rinkB` (`home/away/penalties/penFoldAt/events/goalFlash/offside/penaltyCall/shootout` + `homeLogo/awayLogo`). `rinkView(s,'b')` makes Rink B look like a normal state so every rule works unchanged; `onRink(s, rink, fn)` applies a mutation to one rink (folds Rink A first); shared live changes (`startClock/stopClock/setPlayLive`) fold both rinks (`foldAll`). Boards: `/b/CODE` = center board (`DualBoard`: both games, clock, period, SHIFT countdown), `/b/CODE?rink=a|b` = side boards (one game each, normal layouts, same clock), `/o/CODE?rink=b` = Rink B banner. Controllers: `/c/CODE` = center (C): clock + period + shift + Rink A/B tabs, can run both games; `/c/CODE?rink=a|b` = controller A / B: only that rink's score, shots, penalties, goal light; no clock, period, timeout, options or new game; keyboard limited to `RINK_KEYS`. QR sheet lists every link in full (watch: boards, `?view=shift`, banners; run: controllers). Labels `opts.labels.rinkA/rinkB`; each rink has a fixed color on every screen (`RINK_COLOR` in Board.jsx: A yellow, B light blue): the RINK A/B pill on the center board, the side board's pill + card frames, the banner tag.
- **Shift clock page** `/b/CODE?view=shift` (`ShiftBoard`): only the shift countdown, huge, plus period · clock; full rink or small ice.
- **Shift (line change) timer** (`opts.shiftMs`, Options → Game, mm:ss, 0:00 = off; works in full rink and small ice): derived from the game clock (`shiftInfo`: pauses with the clock, starts over by itself; a new period starts a new shift; `resetShift` = "↺ New shift", asks first: `confirm.newShift`); the control page buzzes once per shift (`shiftBuzzer`, de-duplicated with `state.shiftBuzzed`). Display: label `opts.labels.shift` ("SHIFT CLOCK") above the seconds, styled like the PERIOD label, and the countdown in a red box on **every layout** when it is on (`.shiftbox` under the clock on arena/full/minimal, `.cshift` under the period on compact, the big box on the small-ice center board; side boards show it too).
- Offside: Control team card "Offside −1/+1" (`addOffside`; count in `home/away.offsides`, no player number). The display shows "OFFSIDE + team" for 5 s (`offsideActive`, `OFFSIDE_SHOW_MS`) in the same reserved slot as GOAL! (GOAL wins); it is logged in the timeline, CSV and totals. Label `opts.labels.offside`. `gameSheet().timeline` lists them in game order with the side (printable sheet: Time | home | away columns).
- `src/Options.jsx` — tabbed options screen (Game, Teams, Keys, Colors, Sounds, Text, Banner, Other). Edits a draft copy, saves via `G.setOptions`.
- `src/styles.css` — one file. Themes are `[data-theme=...]` CSS-variable sets; per-element color overrides are `--c-*` vars set by `useAppearance`.
- `supabase.sql` — tables `games` (public select only), `game_keys`, `operators` (+ `is_admin`), `operator_sessions`, `teams` (no direct access); RPCs `create_game`, `save_game`, `check_key`, `server_now`, `operator_login/logout/check/whoami`, `get_game_key`, `delete_game`, `team_list/save/update/delete`, `set_operator` (SQL editor only). Safe to re-run; the later definitions in the file win.

### Clock design (important)
The clock is NOT ticked over the network. State stores `{remainingMs, running, since}`; every device derives the current value locally with `clockRemaining(state, now)`. `now` comes from `src/clock.js` (`now()` = `Date.now()` + offset to the server), never from `Date.now()` directly: in live mode `sync.js` measures the offset via the `server_now()` RPC (fallback: HTTP Date header) on load, every 5 min and on tab focus, so a phone with a wrong system time still agrees with the TV. `TimeBadge` shows the offset when it exceeds 0.5 s. **Penalties (per the standalone-scoreboard brief, IIHF):** they count REAL elapsed time while `live = clock.running && playLive` (playLive = the whistle / "All penalties Start/Stop"), never the game clock, so a clock correction never moves them. Stored per penalty: `elapsedMs` as of `state.penFoldAt`; `penaltyView()` derives remaining/status for every screen. Max 2 running per side (Rule 26.1), later ones `waiting` (board shows `+N`). A goal by the side with more skaters ends the scored-against side's least-time running minor (double minor: only the current 2:00); never majors/misconducts, never on a penalty-shot goal (Rule 16.2). **The operator is asked first** (`releaseCandidate`; Control sheet "Goal + release #12" / "Goal, keep #12 in the box", from + GOAL, + GOAL 📯, score +1 and the goal keys; off with Options → Other → `confirm.releaseOnGoal`); `addScore(..., { release: false })` keeps it; the goal event records `release: { penaltyId, player, done }` and the game sheet shows "ended #12" / "kept #12" (text, CSV End column, printable). Misconduct (10:00) takes no slot and no strength. Call `foldPenalties()` before anything that changes `live` or the penalty list (the mutations in game.js already do). The **control page is the authority**: it stops the clock at 0, prunes expired penalties, ends timeouts (interval in Control.jsx).

### State shape (see `newGame()` in game.js)
`home/away {name, score, shots, color}`, `playLive`, `penFoldAt`, `showTimeOfDay`, `period` ('1'..'n','OT','SO'), `periodLengthMs`, `skaters` (3/4/5), `theme`, `clock`, `penalties[]`, `horn`/`buzzer` counters (bump = play), `timeout`, `goalFlash`, `events[]` (game log: goal/penalty/timeout/so with period + clock, capped at 400; −1 on a score undoes the last goal entry), `shootout {home[], away[]}` ('goal'|'miss'), `opts` (see options.js), `updatedAt` (used to drop stale echoes).

Penalty kinds (`kindOf`): `minor`/`double`/`major` take one of the two slots and reduce strength. `coincidental: true` (RB 19.1), `misconduct` and `game` (game misconduct, 20 min in the log, no clock) never take a slot, never change strength and are not on the display/banner (`onPenaltyClock`). A misconduct starts only when the same player's slot penalties are over. A penalty-shot goal (`addScore(..., {penaltyShot: true})`) releases nobody. OT length is `opts.otMinutes` (IIHF: 5 round robin, 10 playoffs).

**Game sheet (IIHF Game Summary style):** `gameSheet(s)` in game.js builds it from `events[]`; `summaryText` / `summaryCsv` / `summaryHtml` (printable, "Save as PDF") render it (Control → 📋 Summary). Times are game time counted up from the start of the game (`eventGameTimeMs`: P2 3:12 with 15-min periods = 18:12; OT after all regular periods). Goal events carry `situation` (EQ/PP1/PP2/SH1/SH2 from skaters on ice at the goal, PS for penalty shots), `scorer`, `a1`, `a2`, `en` (set afterwards with `editGoal`; the team card shows "✎ Scorer" for the last goal without one, and the Summary sheet lists goals to edit). Penalties log a `penaltyEnd` event when they expire, are released by a goal or removed after running (End column). Every shot on goal is a `shot` event (−1 removes the team's last one); shots appear only in the Timeline (time + side) and the SOG total, not in a per-period table (operator's call). Not on our sheet: rosters, goalkeepers/saves, officials, penalty start ≠ call time.

## Decisions already made
- **Desktop app: only what Pai asks for** (2026-10-19): the web app comes first; desktop work only on request (remote controllers via the online link were requested).
- **Vercel Hobby = 100 deployments/day.** Branch `claude/*` previews are off (`vercel.json` git.deploymentEnabled) so only `main` deploys; batch changes instead of pushing every small fix.
- **Operator login.** Operators log in at `/login` (username + password, table `operators`, bcrypt via pgcrypto). The session token (30 days, table `operator_sessions`) lives in localStorage `rinkboard:session` and is passed to `save_game`/`check_key`/`create_game` instead of a game key; it never goes in a URL. Only a logged-in operator can create a game. Add/change an operator in the Supabase SQL editor: `select public.set_operator('name','password');` (logs that user out). Wrong password costs 1 s; no lockout a stranger could trigger.
- **Watching is public:** `/b/`, `/o/`, `/live` need no login.
- Per-game helper links still work: each game gets a random key in `game_keys`; a logged-in operator gets it via `get_game_key` (Control → QR → Copy operator link) and `?k=KEY` lets a helper run that one game without logging in.
- Sound is ON by default on both the display and the control page (horn/buzzer play on both; unlocks itself where allowed, e.g. OBS; otherwise on the first tap anywhere). Mute choice is remembered per device (`rinkboard:sound:board`, `rinkboard:sound:ctl`).
- Supabase SQL functions are plain `language sql` on purpose: plpgsql bodies time out through the Supabase MCP connector.
- Options sync with the game (stored in `state.opts`) so phone changes reach the TV.
- Images (logos, banners) are stored as resized data-URLs (≤512 px) inside state; fine for Supabase jsonb.
- Skipped from PC Scoreboards on purpose: video queue, CSV data output, hardware relays, shot clock, screen size/position, log file.
- Fonts from Google Fonts (Barlow Condensed default; Share Tech Mono for 7-segment look).
- Shootout attempts are recorded (●/○ on display, banner, control) but the deciding goal is **not** added automatically: the operator taps + GOAL for the winner.
- Control page mirrors the PC Scoreboards control screen: All times / Period time / All penalties Start-Stop, Reset, Show time of day, Timeouts, Goal light ◁ None ▷, Correction (set clock), Help (keys sheet), New game, Show scoreboard; penalty list with + (add, infraction templates from `opts.penaltyTemplates`), ✎ edit, ✕ remove, ••• ±1/±5 s.
- Penalty quick picks (`opts.penaltyTemplates`, not editable in Options) follow IIHF 2026/27: each infraction's usual minutes (most 2′; spearing / butt-ending / high-sticking injury 4′; fighting 5′+GM). `majorGM: true` = IIHF has no plain major for it, so picking 5 min on the penalty sheet turns on "+ game misconduct". `templatesV: 2`; older games get the new list once in `withDefaults`.
- Keyboard defaults copy PC Scoreboards Options → Keys (`DEFAULT_KEYS` / `KEY_GROUPS` in options.js), plus Space toggle and ↑/↓ ±1 s.
- Display layouts (`opts.layout`): **`compact` is the default** (Pai, 2026-10-19; the e2e test build keeps `arena` via `VITE_DEFAULT_LAYOUT=arena` in .env.test because most display tests use its selectors; games saved earlier keep their layout). `arena`: team logo above the name, tournament logo above the clock, one penalty box per team under its card (no title: the team color stripe and position say whose) with 3 positions (IIHF off-ice handbook; running first, waiting dimmed, then +N), optional background photo `opts.bgImg` (JPEG ≤1280 px, darkened so the numbers stay readable). `compact`: one broadcast panel (the operator's earlier OBS design: navy gradient, clock in a green box, period number, tournament logo, scores in team colors, penalties under each team only when present, date + time of day along the bottom). `full`: team logo faded behind the score, 2 penalties + "+N" under the clock. `minimal`: big numbers only.
- Control page layout (≥900 px): clock card in the middle (status, ±1/±5 s beside the clock, START/STOP, All times / Period time / All penalties, ±1:00 / SET, period, horn/buzzer/time of day, timeouts, goal light), team cards left/right (tap the name to rename/recolor; "+ GOAL" silent and "+ GOAL 📯" goal + horn side by side), and everything fits one screen (sizes use vh). Menu row and the status line (game code · who is logged in / log out, or "game key only · Log in" · live) sit at the bottom.
- Goal on the display: only the scoring team's card background blinks, for as long as the goal light is on (`opts.goalOffSec`), restarting on each new goal (React key = `goalFlash.at`); the control page's team card blinks the same way. Numbers and shots never move; "GOAL! + team name" blinks in `.evslot`, a fixed-height slot under the strength chip that is always reserved (so nothing moves or overlaps; strength stays visible).
- The display always fits the window (no scrolling, nothing cut): every display size is `calc(N * var(--u))` with `--u: min(1vw, 1.75vh)` (scales with the shorter side), the grid row is `minmax(0, 1fr)` and cards shrink (logos first) rather than grow. Checked at 1000×510, 1280×720, 1366×600, 1920×1080, 390×844 and 844×390 for full/arena/compact. Don't add plain `vw`/`vh` font sizes to `.board` rules.
- Display full screen: double-click anywhere or the ⛶ button (bottom-right; hidden until hover on a see-through display or in full screen). Double-click never selects text (`user-select: none`). On open the board shows "Double-click for full screen" for 4 s, then fades (`FullscreenHint`; not in OBS `window.obsstudio`, not when the window already fills the screen).
- Tournament logo on compact/full fills the space left in the middle column (`.cllogo` / `.logofill`, capped at 30u / 26u).
- Every display card has the same rounded frame in every theme (`--frame` per theme; team color stays on the top/left edge).
- Time of day (`state.showTimeOfDay`, Control → Show time of day, key M) is shown UNDER the game clock on the display and banner, never instead of it.
- Display background: `opts.bgOpacity` (default 50 %; 100 = solid for a TV). Below 100 the page is see-through for OBS / camera-app overlays: cards stay solid, the middle (period/clock) is a card too, the status line and brand are hidden and the sound button only shows on hover. A background photo (`opts.bgImg`, arena) overrides it.
- Tournament logo + background photo are in Options → Teams (top).
- Team logos page `/teams` (Teams.jsx): upload several logos at once; each becomes a saved team named from the file name (`nameFromFile`: "bangkok_bears.png" → "Bangkok Bears"); rename, recolor, replace logo (320 px), delete. Linked from Home, Options → Teams and the control team sheet.
- Saved teams (`src/teamLibrary.js`): name, color, logo kept in this browser's localStorage (`rinkboard:teams`), added when Options or the control team sheet is saved; picked with one tap in both places.
- **Shared team library** (table `teams`, RPCs `team_list/save/update/delete`, client in `sync.js`): one list for every operator. Anyone can read it; a logged-in operator uploads on `/teams`; the uploader edits/deletes their own; the admin (`operators.is_admin`, only `paichanut`) can replace any logo (e.g. to fix a missing transparent background: ⬇ download, fix, click the logo to replace). Saving Options / the team sheet adds a team only if the name is new (`shareTeamIfNew`, never overwrites an admin fix). Pickers (`SavedTeams`) show shared teams first, then this browser's. Desktop app reads it read-only via `GET https://livebyscoreboard.vercel.app/api/teams` (`api/teams.js`, Vercel function using the server's Supabase env; `vercel.json` rewrites skip `/api/`) and can "Keep on this computer".

## Testing

```bash
npm run test:unit          # node:test — tests/unit/game.test.js (clock, penalties, strength, periods, option merge)
npm run test:e2e:install   # once: downloads Chromium for Playwright
npm run test:e2e           # Playwright — tests/e2e/*.spec.js, `build:test` (local store enabled) + `vite preview` on :4173
npm test                   # both
```

E2E tests open the control page and the board in the same browser context (test build's local store = localStorage + BroadcastChannel), each with a unique game code. `PW_CHROMIUM_PATH=/path/to/chrome` uses a system Chromium instead of the downloaded one. Helpers live in `tests/e2e/helpers.js`. Keep game-rule tests in the unit file; keep e2e tests to flows a user would do.

## Conventions
- Plain JS + JSX, no TypeScript. Functional components, hooks, no state library.
- Keep hockey rules in game.js; keep UI dumb.
- Commit messages: short imperative summary line.
