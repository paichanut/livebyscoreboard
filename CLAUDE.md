# Live by Scoreboard — project context for Claude Code

**Name: Live by Scoreboard** (not "Rinkboard"; that old name survives only in localStorage keys `rinkboard:*` and the Supabase project name, kept so saved logins/keys still work). Web-based ice hockey scoreboard (React + Vite, hosted on Vercel, live sync via Supabase).
**Production: https://livebyscoreboard.vercel.app** (Vercel project `livebyscoreboard`, auto-deploys main). Supabase project `rinkboard` (ap-southeast-1). The old Vercel project `rinkboard` is deleted; use only livebyscoreboard.
Owner: Pai. Built for the "3on3 Paradise 2026 OCT" tournament and future rink use; also used as an OBS overlay for streams.
Reference product we are mirroring: PC Scoreboards "Hockey Scoreboard Pro v3" (Windows desktop) and ScoreLeader's public-link model.

## Run / build

```bash
npm install
cp .env.example .env     # VITE_SUPABASE_URL / VITE_SUPABASE_ANON_KEY are REQUIRED; without them every route shows Setup.jsx
npm run dev              # http://localhost:5173
npm run build            # dist/ (Vercel builds this automatically)
```

**Cloud mode only.** Production never falls back to a local store: no keys → `Setup.jsx` with the setup steps. The same-browser local store (localStorage + BroadcastChannel) still exists in `sync.js` but only for the test build (`npm run build:test` = `vite build --mode test`, which loads `.env.test` → `VITE_ALLOW_LOCAL=1`). Decision made after a tournament-day mix-up where Chrome and OBS each had their own "copy" of the game.

## Architecture

- `src/game.js` — **pure** state model + mutations. No React, no network. All hockey logic lives here (clock, periods, penalties, strength 5v4/4v3, timeouts, goal flash). Keep it pure.
- `src/options.js` — options schema + `defaultOptions()` + `withDefaults()` (deep-merges defaults into older saved games). Add new options here first.
- `src/sync.js` — store abstraction. Supabase realtime when env keys set; local store only when `VITE_ALLOW_LOCAL=1` (test build), otherwise `createStore` throws and App shows Setup. Reads are public; **writes go through `save_game(id, key, state)` RPC** which checks the operator key. Rapid taps are coalesced (~80 ms). `createGamesList()` feeds the `/live` page (table-wide realtime, or a localStorage scan).
- `src/i18n.js` — control-page UI strings (`en`, `th`), `translator(lang)`. Chosen by `opts.uiLang` (Options → Text). Display labels are separate free text in `opts.labels`. Options tab names + Save/Cancel are translated; the Options body is still English.
- `src/useGame.js` — React hook `useGame(gameId, {key, canWrite})` → `[state, update(fn), access]`. `update` takes a function `(state) => newState` (use game.js mutations). `useGameId()` parses `/b|c|o/CODE` or `?g=`.
- `src/useOptions.jsx` — `useAppearance(s)` applies theme/colors/font to `<html>`; `useGameSounds(s, enabled)` plays configured sounds on events (display side only).
- `src/horn.js` — Web Audio playback. Samples from `public/sounds/*.mp3`: `horn-nhl` (4.2 s, the default goal horn) and `horn-nhl-short` are an NHL-style three-chime air horn synthesized by `scripts/make-nhl-horn.py` (no recordings used); horn, horn-short, horn-loop, buzzer are converted from PC Scoreboards WAVs (mono 48 kbps) are decoded once after `unlockAudio()` (needs a user gesture); synth horn/buzzer/beep are the fallback. `playSound(kind)` takes a `SOUND_CHOICES` value from options.js. Goal horns 2 s or longer (horn-nhl, horn, horn-loop, synth) fade out over their last second (`HORN_FADE_SEC`); short horns and the buzzer play as they are.
- Event types in `events[]`: shot, offside, goal, penalty, penaltyEnd, timeout, so.
- Penalty call on the display: a new penalty shows "◀ PENALTY" (home, left) / "PENALTY ▶" (away, right: the arrow points at the side that committed it, `Pointed` in Board.jsx; no team name) over "#12 HOOKING 2:00" for 15 s (Pai, 2026-10-19; was 5 s) in the `.evslot` (`state.penaltyCall`, `penaltyCallActive`, `PENALTY_SHOW_MS`; a 2nd penalty on the same player within 2 s joins it: "#7 FIGHTING 5:00 + GM"; follows edits, gone if removed). GOAL! wins; otherwise the newer of offside / penalty. The penalty boxes still show only number + time (IIHF arena style). Long text shrinks to fit (`72 / length` u).
- **Small ice** (`opts.smallIce`, chosen on Home "Full rink / Small ice" → `/c/CODE?mode=small`, or Options → Game → Rink): two games on one rink sharing ONE clock, period, whistle, timeouts and shift. Rink A = the normal state fields, Rink B = `state.rinkB` (`home/away/penalties/penFoldAt/events/goalFlash/offside/penaltyCall/shootout` + `homeLogo/awayLogo`). `rinkView(s,'b')` makes Rink B look like a normal state so every rule works unchanged; `onRink(s, rink, fn)` applies a mutation to one rink (folds Rink A first); shared live changes (`startClock/stopClock/setPlayLive`) fold both rinks (`foldAll`). Boards: `/b/CODE` = center board (`DualBoard`: both games, clock, period, SHIFT countdown), `/b/CODE?rink=a|b` = side boards (one game each, normal layouts, same clock), `/o/CODE?rink=b` = Rink B banner. Controllers: `/c/CODE` = center (C): clock + period + shift + Rink A/B tabs, can run both games; `/c/CODE?rink=a|b` = controller A / B: only that rink's score, shots, penalties, goal light; no clock, period, timeout, options or new game; keyboard limited to `RINK_KEYS`. QR sheet lists every link in full (watch: boards, `?view=shift`, banners; run: controllers). Labels `opts.labels.rinkA/rinkB`; each rink has a fixed color on every screen (`RINK_COLOR` in Board.jsx: A yellow, B light blue): the RINK A/B pill on the center board, the side board's pill + card frames, the banner tag.
- **Timeout / warm-up in the big clock** (Pai 2026-10-25): `clockDisplay(s, now)` in game.js → `{ kind: 'game'|'timeout'|'warmup', ms }`; while a timeout or the warm-up runs, the big clock on every board layout (and the banner, label instead of the period) counts it down in whole seconds, with a chip `ClockNote` ("TIMEOUT · team" / "WARM-UP", `.timeout`/`.ctimeout` + `.warmup`); when it ends the game time is back exactly as it was. The control page's own clock always shows the game time (the timeout / warm-up button counts down). **Warm-up** button next to the timeouts: `startWarmup(s, opts.warmupSec)` (default 60 s, Options → Game → Warm-up; stops the clock), `state.warmup = { durationMs, since }`, ended by the control's authority interval at 0 (`clearWarmup`), by "— end", or by starting the clock; sound `sounds.warmupEnd` (buzzer), label `labels.warmup`.
- **Type the clock** (Pai 2026-10-25): tap the control page's big clock (`ClockField` in Control.jsx) → it turns into a field; Enter / leaving it sets the time (`parseClockInput`: "12:34", "12:34.5", "45.5", digits "1234" = 12:34, "45" = 45 s; stops the clock like SET; count-up clocks take the shown value), a wrong entry turns red, Esc cancels.
- **Shift clock page** `/b/CODE?view=shift` (`ShiftBoard`): only the shift countdown, huge, plus period · clock; full rink or small ice.
- **Shift (line change) timer** (`opts.shiftMs`, Options → Game, mm:ss, 0:00 = off; works in full rink and small ice): derived from the game clock (`shiftInfo`: pauses with the clock, starts over by itself; a new period starts a new shift; `resetShift` = "↺ New shift", asks first: `confirm.newShift`); **every screen sounds its own buzzer** (useGameSounds, from its own clock — nothing goes over the network) the instant its shift digit shows 0, scheduled to the millisecond; once per shift; a page opened on a 0 stays quiet. Clocks redraw on the exact second boundary (`useClockTick`), and "New shift" starts on a whole game-clock second, so the game clock, the shift digit and the buzzer change together (e2e: buzzer within 60 ms of the 0). Display: label `opts.labels.shift` ("SHIFT CLOCK") above the seconds, styled like the PERIOD label, and the countdown in a red box on **every layout** when it is on (`.shiftbox` under the clock on arena/full/minimal, `.cshift` under the period on compact, the big box on the small-ice center board; side boards show it too).
- **Event display** (`opts.eventDisplay`, Options → Game, Pai 2026-10-24): `board` (default: GOAL! / PENALTY / OFFSIDE in the `.evslot` and the referee card) or `big` (`BigEvent` in Board.jsx: the event covers the whole scoreboard for as long as it shows — GOAL! + team (+ logo), PENALTY with the referee figure, #player, infraction, time, OFFSIDE with its arrow; the scoreboard under it is hidden meanwhile and the small versions step aside). For small overlays (camera apps, a stream corner).
- **Web overlay link** `/b/CODE?overlay` (QR sheet "Web overlay", desktop links; not in the footer): always fully see-through whatever `bgOpacity` (so the same game stays solid on the TV): no panel/card/box/event backgrounds at any moment, text with a dark outline (`.board.overlay`), no full-screen button/hint.
- Shots on the display: label `opts.labels.shots` = "SHOT ON GOAL" (Pai 2026-10-23; old default "SHOTS" migrates once in `withDefaults`, a typed label stays), always **above** its number on every layout (`.shots` is a column; compact `.clabel` over `.cshots`). The banner strip keeps label + number on one line.
- Offside: Control team card "Offside −1/+1" (`addOffside`; count in `home/away.offsides`, no player number). The display shows "◀ OFFSIDE" / "OFFSIDE ▶" (arrow at the side that was offside) for 15 s (`offsideActive`, `OFFSIDE_SHOW_MS`; Pai 2026-10-19) in the same reserved slot as GOAL! (GOAL wins); it is logged in the timeline, CSV and totals. Label `opts.labels.offside`. `gameSheet().timeline` lists them in game order with the side (printable sheet: Time | home | away columns).
- `src/Options.jsx` — tabbed options screen (Game, Teams, Keys, Colors, Sounds, Text, Banner, Other). Edits a draft copy, saves via `G.setOptions`. **Live preview** (Pai 2026-10-19): `LivePreview` = the real scoreboard in an iframe (`/b/CODE?preview=1` → Board.jsx `PreviewBoard`: shows the unsaved draft game posted by Options (`lbs-preview` message, `lbs-preview-ready` asks for it), no store, no sound, no fullscreen/sound buttons), sticky at the top of Colors and Text, under the layout buttons in Game. Theme presets show a sample in their own colors (`.themechip`, `[data-theme]` on the sample; `[data-theme="dark"]` repeats the :root colors for that). Fonts are buttons written in their own font (`.fontchip`).
- Fonts (`FONT_CHOICES`): Barlow Condensed, Share Tech Mono, Oswald, Anton (Google link in index.html; @fontsource in fonts-offline.js for the desktop app) and **LCD digital / LCD digital italic** = DSEG by keshikan (SIL OFL 1.1, `public/fonts/DSEG*.woff2` + DSEG-LICENSE.txt; Pai wanted an "Overtime LCD" look, a paid font): numbers/colon/point from DSEG7 Modern (clean 0), letters from DSEG14 Modern, joined by `unicode-range` in styles.css. ### Clock design (important)
The clock is NOT ticked over the network. State stores `{remainingMs, running, since}`; every device derives the current value locally with `clockRemaining(state, now)`. `now` comes from `src/clock.js` (`now()` = `Date.now()` + offset to the server), never from `Date.now()` directly: in live mode `sync.js` measures the offset via the `server_now()` RPC (fallback: HTTP Date header, counted as 1 s rougher) — 8 round trips on load, then 1 every 10 s, 3 on tab focus / back online (Pai 2026-10-24) — so a phone with a wrong system time still agrees with the TV. `src/timesync.js` (pure): `createTimeFilter` keeps the fastest round trip of the last 5 min (offset ±rtt/2, NTP style); a sample whose range can't overlap the best one is a real clock move only once a second fresh one agrees (then the old samples go). Steering in clock.js (`steerShift`): clock stopped (`setClockRunning`, called by the stores with `state.clock.running`) or a change over 0.1 s → at once; smaller while running → slides over 1 s (tenths never repeat/skip). Synced pages count from `performance.now()` (`useMonotonicClock`; a phone setting its own clock mid-game doesn't jump; a sleep/clock step > 1 s resets the filter). The server itself is NTP/atomic-synced (AWS), so this is the atomic clock to within the network. The desktop viewer (`/api/time`) uses the same filter; the desktop's online-game `skew` is measured the same way every 10 s in share.cjs and re-sent when it moves ≥ 20 ms; `gameSkew` changes are steered too. `TimeBadge` shows "sync ±N ms" (half the best round trip; red over 100 ms) on the control status line and a solid board's status line, plus the device's own offset when it exceeds 0.5 s. **Penalties (per the standalone-scoreboard brief, IIHF):** they count REAL elapsed time while `live = clock.running && playLive` (playLive = the whistle / "All penalties Start/Stop"), never the game clock, so a clock correction never moves them. Stored per penalty: `elapsedMs` as of `state.penFoldAt`; `penaltyView()` derives remaining/status for every screen. Max 2 running per side (Rule 26.1), later ones `waiting` (board shows `+N`). A goal by the side with more skaters ends the scored-against side's least-time running minor (double minor: only the current 2:00); never majors/misconducts, never on a penalty-shot goal (Rule 16.2). **The operator is asked first** (`releaseCandidate`; Control sheet "Goal + release #12" / "Goal, keep #12 in the box", from + GOAL, + GOAL 📯, score +1 and the goal keys; off with Options → Other → `confirm.releaseOnGoal`); `addScore(..., { release: false })` keeps it; the goal event records `release: { penaltyId, player, done }` and the game sheet shows "ended #12" / "kept #12" (text, CSV End column, printable). Misconduct (10:00) takes no slot and no strength. Call `foldPenalties()` before anything that changes `live` or the penalty list (the mutations in game.js already do). **STOP has zero lag on the desktop app** (Pai: most games run on the desktop app): every start/stop control (big START/STOP, All times / Period time start-stop, their keys) acts when the button/key goes **down** (`onPress` in Control.jsx: pointerdown; a keyboard click with `detail 0` still works; held keys don't repeat), and stamps the clock with the time of the press (`nowAt(e.timeStamp)` in clock.js → `toggleClock/stopClock(s, now)`, `startClock(s, { now })`), so the stopped time is the clock at the instant of the press even if the page was busy. Measured (Electron): press → HDMI scoreboard 2–4 ms, on screen the next frame; stopped value = the time at the press ±1 ms. The **control page is the authority**: it stops the clock at 0, prunes expired penalties, ends timeouts (interval in Control.jsx).

### State shape (see `newGame()` in game.js)
`home/away {name, score, shots, color}`, `playLive`, `penFoldAt`, `showTimeOfDay`, `period` ('1'..'n','OT','SO'), `periodLengthMs`, `skaters` (3/4/5), `theme`, `clock`, `penalties[]`, `horn`/`buzzer` counters (bump = play), `timeout`, `goalFlash`, `events[]` (game log: goal/penalty/timeout/so with period + clock, capped at 400; −1 on a score undoes the last goal entry), `shootout {home[], away[]}` ('goal'|'miss'), `opts` (see options.js), `updatedAt` (used to drop stale echoes).

Penalty kinds (`kindOf`): `minor`/`double`/`major` take one of the two slots and reduce strength. `coincidental: true` (RB 19.1), `misconduct` and `game` (game misconduct, 20 min in the log, no clock) never take a slot, never change strength and are not on the display/banner (`onPenaltyClock`). A misconduct starts only when the same player's slot penalties are over. A penalty-shot goal (`addScore(..., {penaltyShot: true})`) releases nobody. OT length is `opts.otMinutes` (IIHF: 5 round robin, 10 playoffs).

**Game sheet (IIHF Game Summary style):** `gameSheet(s)` in game.js builds it from `events[]`; `summaryText` / `summaryCsv` / `summaryHtml` (printable, "Save as PDF") render it (Control → 📋 Summary). Times are game time counted up from the start of the game (`eventGameTimeMs`: P2 3:12 with 15-min periods = 18:12; OT after all regular periods). Goal events carry `situation` (EQ/PP1/PP2/SH1/SH2 from skaters on ice at the goal, PS for penalty shots), `scorer`, `a1`, `a2`, `en` (set afterwards with `editGoal`; the team card shows "✎ Scorer" for the last goal without one, and the Summary sheet lists goals to edit). Penalties log a `penaltyEnd` event when they expire, are released by a goal or removed after running (End column). Every shot on goal is a `shot` event (−1 removes the team's last one); shots appear only in the Timeline (time + side) and the SOG total, not in a per-period table (operator's call). Not on our sheet: rosters, goalkeepers/saves, officials, penalty start ≠ call time.
